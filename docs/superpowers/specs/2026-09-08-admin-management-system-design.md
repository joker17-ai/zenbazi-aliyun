# ZenBazi 管理系统设计

日期：2026-09-08

## 目标

在现有后台上扩展一个真正可操作的管理系统，让管理员无需猜测记录序号，即可查看用户信息、付款订单以及付款后生成的报告内容。界面继续使用现有的米白、朱红和深灰视觉语言，不改变前台品牌风格。

## 范围

本阶段包含四个后台页面：

1. **数据总板**：用户总数、已付款用户、待付款订单、累计实收、已生成报告和生成失败数，并展示最近活动。
2. **用户管理**：按姓名、手机号、会话编号或记录序号搜索；按月份、付款状态筛选；查看用户出生信息、套餐、优惠余额、付款状态和创建时间。
3. **付款订单**：展示商订单号、用户、渠道、应付金额、状态、平台流水号、创建时间和付款时间；支持按订单状态、支付渠道和关键词筛选。
4. **生成内容**：展示报告是否已生成、生成时间和错误状态；从用户或订单点击“查看生成内容”后，直接打开相应内容，不再要求手工输入“报告序号”。

本阶段不包含退款操作、手工修改付款状态、删除用户、财务对账导出或多管理员权限系统。它们可以在真实订单运行稳定后增加。

## 页面结构

后台登录方式保持不变。登录后使用同一页面内的标签导航：

- 数据总览
- 用户管理
- 付款订单
- 生成内容

桌面端使用表格，窄屏使用可横向滚动的表格和抽屉式详情。现有月份输入改为标准月份选择器。所有列表统一提供搜索、筛选、刷新、加载状态、空状态和错误提示。

用户列表每一行提供“查看详情”和“查看生成内容”。付款订单每一行提供“查看订单”和“查看生成内容”。报告内容在详情抽屉中阅读，保留换行和段落，不再直接显示难读的 JSON；需要排查问题时可展开“原始数据”。

## 数据关系

后台以数据库为权威数据源：

- `user_records` 保存用户及其付款权益。
- `payment_orders` 保存微信和支付宝订单。
- `report_records` 保存报告正文、禅语及 Notebook 位置。
- `decrypt_audit_logs` 记录管理员查看敏感报告的行为。

用户、订单和报告通过 `session_id` 关联；报告同时使用 `month_key + sequence` 作为稳定定位键。数据库未启用时，后台保留现有统计兼容视图，但明确显示“数据库未启用”，不伪造用户、订单或报告数据。

## 后台接口

所有新增接口都要求有效的管理员令牌：

- `GET /api/admin/overview`
- `GET /api/admin/users`
- `GET /api/admin/users/:id`
- `GET /api/admin/payments`
- `GET /api/admin/payments/:id`
- `GET /api/admin/reports`
- `GET /api/admin/reports/:id`

列表接口支持 `page`、`pageSize`、`month`、`status`、`provider` 和 `query` 参数。服务端限制最大分页大小，并返回 `items`、`page`、`pageSize` 和 `total`。报告详情接口解密内容后返回，并写入审计日志。

旧的 `/api/admin/metrics` 和 `/api/admin/decrypt` 暂时保留，避免已有后台或部署脚本失效；新界面不再暴露手工解密入口。

## 安全与隐私

- 付款状态只能来自已验签的微信或支付宝回调/主动查询，后台只读，不提供“手工改成已付款”。
- 不向浏览器返回商户私钥、支付密钥、完整回调报文或内部加密材料。
- 列表中默认遮盖手机号中间四位和会话编号；详情中才显示完整业务字段。
- 每次查看解密报告都记录管理员、目标记录和时间。
- 搜索和分页参数在服务端验证，数据库查询全部参数化。
- 未配置数据库时接口返回明确的服务不可用错误，而不是展示空的成功数据。

## 错误处理

- 数据加载失败时保留当前页面并显示可重试提示。
- 用户、订单或报告不存在时返回 404。
- 订单已付款但报告未生成时显示“等待生成”，并展示订单已付款时间。
- 报告生成失败时显示失败原因摘要，不泄露服务器堆栈。
- 管理员令牌过期时返回登录页，并保留原本要访问的标签页。

## 测试与验收

实现使用服务端数据库函数测试、后台接口测试和前端交互测试。验收条件：

1. 管理员可以从用户列表一键打开对应报告，不输入序号。
2. 管理员可以查看微信和支付宝订单的金额、状态及付款时间。
3. 搜索、月份筛选、付款状态筛选和分页正常工作。
4. 未付款用户不能显示为已付款，未验签回调不能改变付款状态。
5. 未配置数据库、空列表、接口错误和令牌过期都有明确界面状态。
6. 原有后台登录和现有前台页面保持可用，视觉风格保持一致。

## 上线要求

新增代码可以先进入仓库，但用户、订单和报告列表要在线上真实工作，服务器必须启用 PostgreSQL，并配置支付平台商户参数。部署时执行数据库建表初始化，重启后端，再发布前端静态文件；上线后分别验证管理员登录、空数据、测试用户、测试订单和报告详情。
